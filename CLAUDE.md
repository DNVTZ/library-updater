# library-update — правила работы

Скрипт обновления версий библиотек Lexema8 для сайтов: таблица Google Sheets → wiki (wiki.lex.lan) →
`updatedPackage.json`, новый столбец версий в таблице, `manualScripts.md` с ручными SQL-скриптами и
выгрузки в `debug/` (только по библиотекам, версия которых поднимается).

## Google Sheets — строго
- **Прогоны на прод-таблице (`spreadsheets.prod` в config.js) запрещены категорически.** Не запускать
  `node index.js` и вообще ничего, что обращается к прод-таблице. Прод запускает только пользователь.
- **Тестовая таблица (`spreadsheets.test`)** — можно прогонять самостоятельно, без разрешения, когда нужно
  проверить изменения: `node testRun.js`.
- Тестовая таблица намеренно отстаёт по обновлениям от продовой, чтобы с wiki приходило больше версий
  для наглядного тестирования. Не «догонять» её и не считать отставание ошибкой.
- Тестовый прогон перезаписывает локальные результаты (`debug/`, `packageVersions.json`,
  `updatedPackage.json`, `manualScripts.md`). Перед прогоном сохранять их копию в scratchpad и
  восстанавливать после.

## Репозиторий
- GitHub-репозиторий публичный. Ключи `libraryUpdaterKey*.json` и любые пароли не коммитить
  (учётка форума — через `FORUM_USER` / `FORUM_PASSWORD`).
- Результаты запуска в `.gitignore`, в git только код и `originalPackage.json`.

## Правила предметной области
- `updatedPackage.json` должен совпадать с `originalPackage.json` символ в символ, кроме версий библиотек.
  Версия меняется только если новая строго выше. Поэтому правка регуляркой по тексту, не через JSON.parse.
- Суффикс версии на wiki — сборка ПОСЛЕ базовой (хотфикс), не пре-релиз: `3.1.19 < 3.1.19-1 < 3.1.20`,
  `-beta.N` тоже после базовой.
- Порядок версий на wiki — источник истины (сверху новее). Нумерация на страницах бывает не по порядку
  (ветки), поэтому диапазон «что ставить» считается по позиции на странице, а не сравнением номеров.
- Скрипты и выгрузки — только по версиям между текущей (не включая) и целевой (включая). Версии с
  заголовком «Проект релиза» / «НЕ БРАТЬ» / «(не брать)» пропускаются.
- Повторный запуск в тот же день перезаписывает сегодняшний столбец, а не добавляет новый.
- Сейчас обновляется только эталонный сайт lexpg (берёт последние версии с wiki). Планируется обновление
  других сайтов с верхней границей = версии lexpg из таблицы (`baseSite` в config.js) — весь пайплайн
  (выбор целевой версии, скрипты, выгрузки) должен учитывать эту границу. Пока не реализовано.

## Стиль кода
- Компактный стиль как в wiki.js: короткие выражения в одну строку, без пробелов внутри скобок,
  однострочные `if` без фигурных скобок.
- Короткие комментарии: шапка модуля и пояснения к неочевидному (регулярки, магические индексы).
- Файловые утилиты (`saveJson`, `saveDebugJson`, `saveMarkdown`) живут в wiki.js в своём `#region`.
- forum.js в работе — комментарии в него не добавлять.

## Соседние папки
Папка выше (`Lexema Libraries`) содержит библиотеки, по которым пользователь выполняет заявки. Эти задачи
к library-update не относятся: при работе над ними папку library-update игнорировать.
